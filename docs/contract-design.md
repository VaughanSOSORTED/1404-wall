# Undeployed contract design for review

An event based inscription contract could keep a monotonically increasing ID in one storage slot and emit `Inscribed(uint256 indexed id, address indexed author, string message, uint256 timestamp)`. A public function should enforce a byte ceiling as well as the UI character ceiling and reject empty messages. The event log is immutable on the canonical chain but normal chain finality and reorganizations still apply. Event logs are not directly readable by other contracts; confirm that off-chain indexing and explorer verification satisfy the product requirement. Discuss fee policy, spam and abuse, moderation of the *interface* (without claiming to erase on-chain content), maximum gas cost and Unicode length rules before implementation. This design is a proposal, not a deployed contract or ABI.
